### Step 5 — If testing breaks

Most likely failure modes and fixes:

| Symptom | Likely cause | Fix |
|---|---|---|
| App crashes on launch | Target membership missing for a Model file | Add to main Evlin iOS target |
| "Cannot find X in scope" compile error | Xcode didn't auto-discover file | Right-click parent folder → Add Files |
| Pairing code POST fails | Backend not running or wrong URL | Run uvicorn locally or deploy to Railway |
| "Authorization required" ack failure | ScreenTimeManager.isAuthorized stale | Use SpikeView's "Request authorization" button |
| Child picker doesn't show apps | FamilyActivityPicker needs live auth | Use `.individual` auth, not simulator |
| Nothing happens after lock command | CommandPoller not started | Check `evlin.childDeviceID` in UserDefaults is set |

## Known issues / TODOs I left for you

1. **Chat UI doesn't yet render `ReceiptCard`** — Phase 5 task. Current Chat shows the action text but not the live status/countdown. Parent won't see "Instagram locked · Unlocks at 14:53" until this is wired.

2. **CategoryDefaults uses positional names** (`category_1`, `category_2`, ...) because `Label(ActivityCategoryToken)` doesn't expose the human name back to us. A Settings UI to rename each category (showing `Label(tok)` next to an editable name) would unblock the Chat resolver's category hint matching.

3. **Legacy ChildModeView has its own old polling** (`startPolling` / `pollTimer`) in parallel to the new `CommandPoller`. Both coexist safely — they hit different endpoints. But if you want one source of truth, the old polling can be removed once you've verified the new path works end-to-end.

4. **Max-mode token transferability** (spike Test 3) is still BLOCKED — never validated because you don't have a Child Apple ID. If Max-mode testing fails when you try it, fall back to Std mode (fully functional).

5. **Bundle IDs in catalog are approximate** — e.g. `com.atebits.Tweetie2` for X, `tv.danmaku.bilianime` for Bilibili. Verify against live App Store entries before shipping. Quickest check: install the app, open iOS Settings → Screen Time → App Limits → pick that app, read the inferred bundle ID from any Device Activity report.

6. **Min lock duration is 15 min** (Apple DeviceActivity limit). Chat system prompt mentions this; resolver clamps silently. If you want sub-15-min support, we'd need a local timer + `ActiveLockStore.sweepExpired()` path, which we deferred per your earlier direction.

7. **Phase 5 APNs** — when you want this, you'll need an APNs auth key from Apple Developer. Then we can wire silent push for near-instant command delivery instead of the 5s foreground poll. Happy to pick this up in a fresh session.
